# Folsom水库研究：数据整理与质量核查报告

日期：2026-10-22。当前阶段仅为数据准备，未进行调度模拟、参数优化或策略比较。

## 结论与使用边界

已建立桌面项目 `C:\Users\yuan0\Desktop\Folsom_水库调度研究`，迁入原始数据，并另外下载加州CDEC官方Folsom站资料进行交叉核查。原工作区来源文件保留；迁移采用复制并校验SHA256，没有移动或覆盖唯一原件。

本轮交付的是“可追溯、带质量标记的数据”以及“一段通过明确筛查的完整水文年”，不承诺整个历史序列全部有效。没有为了连续性补值，没有把可疑负入流截成零，没有拼接不同来源的数值。

优先可用样本：**2011水文年，2010-10-01至2011-09-30，共365天**。官方入流、出流、蓄水、蒸发及防洪控制库容五项完整；无负数、无跨日OBS DATE差异、无非空来源标记。日水量平衡残差绝对值最大0.001214876 TAF，约1.215 acre-ft，通过本轮0.1 TAF复核阈值。

这段数据适合验证数据读取、单位转换和后续方法，不足以单独评价长期可靠性、极端干旱适应性或历史管理优劣。通过筛查也不证明各字段是相互独立的直接观测；尤其官方蒸发本身是计算量，入流也可能含水量平衡计算成分。

官方数据下载范围1994-01-01至2016-09-30。接口URL、下载日期、文件哈希保存在 `docs/cdec_download.json`。站点元数据及GitHub数据文件的提交信息也已保存。GitHub数据文件最近一次路径提交记录为 `98bf8320f2d00045ad20864b2878f44dd021c25a`；下载文件自身仍以SHA256识别。

## 二、官方字段与单位统一

| CDEC传感器 | 原字段 | 原单位 | 整理后字段与单位 |
|---|---|---|---|
| 15 | STORAGE | AF | storage_taf，TAF |
| 76 | INFLOW | CFS | inflow_taf_per_day，TAF/day |
| 23 | OUTFLOW | CFS | outflow_taf_per_day，TAF/day |
| 74 | EVAP | CFS | evap_taf_per_day，TAF/day |
| 94 | TOC STO | AF | tocs_taf，TAF |

换算：AF÷1000=TAF；CFS×86.4÷43560=TAF/day；1 TAF=1233481.83754752 m³。CFS在这里是日均流量，换算后代表一天水量，不能直接与库容相加。

总出流不等于实际用户取水，TOCS是报告的运行控制库容，不是水库总容量，也不是独立需水数据。原始DATE TIME与OBS DATE均保留，整理表按DATE TIME列日期排列，不擅自平移日期。

## 三、清洗检查结果

### GitHub历史输入

- 共40908天，1904-10-01至2016-09-30，日期无重复、无缺日。
- 其中18627天缺少蓄水与出流，集中在1955-10-01之前。此部分保留作背景，不能进入四项齐全的历史平衡核查。
- 从1955-10-01起四项数值虽齐全，仍有138天入流恰为0.001 TAF，已标为“疑似下限处理值”，没有凭猜测修正。
- 148天平衡残差超过0.1 TAF，列入复核清单。最大约188.635 TAF，发生在1970-02-28；这类记录不能只凭无空值判断有效。
- 485天历史蓄水超过项目配置975 TAF。超出简化模型容量不等同于观测错误，因此不裁切历史库容。

### 官方CDEC日记录

原始长表38805条传感器记录，统一日历后共8309天。没有同一传感器同一天的重复记录，字段单位符合元数据。非数值记录851条被转换为缺失，但原始VALUE仍完整保存在长表中。

| 变量 | 全下载日历中的缺失天数 |
|---|---:|
| 蓄水 | 11 |
| 入流 | 301 |
| 出流 | 62 |
| 蒸发 | 0 |
| 防洪控制库容TOCS | 3217 |

上述TOCS缺失包括传感器记录开始前的日期，不能全部解释成设备故障。数值有效记录中有1134条OBS DATE与记录日期跨日不一致，250条带非空来源标记；一条入流为负，日期2000-10-22，数值-112 CFS。来源标记语义尚未逐项确认，不将它们一律判断为错误或一律放行。

四项核心水量字段完整的日期7983天；五项字段均完整的日期5081天。完整性只是筛查条件，不代表这些天全部没有其他问题。逐日标记、年度覆盖率与异常明细均已输出。

### 两来源交叉核查

多数同日值接近，但并非完全一致；交叉核查结果保存在 `crosscheck_summary.csv` 和 `official_github_crosscheck.csv`。例如蓄水8298对有效同日记录中，7821对差异不超过0.01 TAF；入流8008对中7653对在该范围内。

差异可能来自版本修订、补值、日界定义或预处理，不能见到差异就直接判定一方错误。本轮不把两来源混成一条“无缺测实测序列”。

## 四、筛查规则与处理决定

水量平衡诊断为：

`residual(t) = S(t) - S(t-1) - Q(t) + R(t) + E(t)`

0.1 TAF仅为人工复核触发阈值，不是已校准的仪器误差上限。残差大也可能涉及未列入的水量项、时段定义或数据修订，不能自动用平衡式反算并覆盖入流。高洪峰不采用箱线图或3σ机械删除。

处理规则：

1. 原始CSV及原始字段不变，所有转换在processed层进行。
2. `---`等非数值按缺失处理，绝不当作0。
3. 数值范围、时间差异、来源标记、平衡偏差分别设置标志；一个“通过”标签不能替代这些具体信息。
4. 缺日和缺值保留在完整日历中，不删除后把相邻行误认为连续天。
5. 不插值TOCS，不用GitHub值填官方缺测，不对负入流自动截零。
6. 除完整水文年外，提供连续通过筛查时段清单，不拼接不相邻的时段。

严格条件下最长连续片段为2011-12-04至2013-05-11，共525天，保存为扩展候选数据。它不是两个完整水文年，后续不能与完整年度统计直接混用。

## 五、需水与运行参数尚未获得的有效性

原始需水文件366项，最后一项与第一项完全相同。原模拟程序每水文年索引前365项，闰年跳过2月29日。因此本轮输出365日月日映射表，明确它是“情景曲线”；并未把第366项重复加进年需水量，也没有创建某一年的实测需水表。

365项合计1861.042608 TAF。此数只能用于描述项目情景，不能据此声称Folsom实际年需求就是该值。闰日如何映射、需水曲线的现实依据、下游生态与用户分配、出库能力、库容适用年代仍需在建模前处理。

项目975 TAF模型上限与USBR页面列出的977000 AF存在差别；现实防洪规则还随时期和上游条件变化。因此folsom.yml保持原样，当前不标为“全部已验证的官方运行参数”。

本轮不进入策略比较。下一步应先确定研究是“公开真实水文输入下的情景试验”还是“历史管理复现”；后者仍缺经核实的需求、完整规程及若干运行信息。长期研究还需复核或合理处理缺测，不能从一个筛选后的年份外推长期结论。

## 文件与复现

- `data/raw/`：原始输入，禁止覆盖。
- `data/processed/`：统一字段、单位和质量标志后的数据。
- `results/data_quality/`：异常清单、年度覆盖、来源差异、连续时段和JSON总结。
- `scripts/clean_folsom_data.py`：本轮清洗脚本，仅需Python、pandas与numpy；从脚本所在项目自动定位数据。
- `docs/`：来源证据、哈希和本报告。

运行：`python scripts/clean_folsom_data.py`。原始文件哈希校验、主样本连续性及质量标记检查结果另见 `results/data_quality/verification.json`。校验与筛查均可通过脚本复现，未进行策略比较。
